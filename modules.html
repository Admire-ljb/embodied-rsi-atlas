各模块分别定义角色交接、工具调用、经验检索和版本选择。模块间以带来源的观测、可回放的运行记录及固定的评价协议交换结果。

AeroWeaver · 应用编排与多智能体协作

编排　沿用 AeroWeaver 的任务上下文、角色分配和技能绑定机制。每个本地 Agent 持有自己的上下文和可用 Skill，通过消息与其他实例协作。角色随任务配置。

接入　本项目拟用 kagent 承载 Agent 实例，用 A2A 适配实例间的消息交换。环境工具通过 MCP 网关调用。

验收　给定离线任务，验证计划、角色与 Skill 绑定、A2A 交接和结果汇总能通过同一运行号关联。

Skill 与 MCP 调用契约

交付　定义 Skill 何时调用 MCP 工具、允许哪些输入、如何解释输出。已有时钟样例用于接口自检。首轮以离线数据接通环境工具，封装检索、摘要与结果核验 Skill。

验收　验证 Skill 的正常、缺失输入及失败回执，核对结果来源和工具版本。

进化面 · 沿用 AgenticMesh

从运行证据到改进候选

输入　执行轨迹、在线评测结果和既有经验。按症状归集失败样本，生成含适用条件与验收用例的目标。

组件　归因器用回放定位可能出错的组件，提议器给出补丁，评判器检查证据是否足以支持送审。经验库保存症状、位置、修改与效果之间的关联。

输出　候选携带父版本、改动范围、证据和已知反例。改进器自身的修改走同一条提交流程，由控制面裁决。

控制面 · 沿用 AgenticMesh

候选验证、发布与回退

输入　候选差异、父版本及冻结的试验对象。控制面维护验证预算、留出样本、风险分级与放行规则。

组件　从模拟交互、对抗测试进入录制回放与隔离沙箱，更高等级采用流量镜像和小流量试发。各阶段将运行结果关联到同一候选版本。

输出　记录接受、拒绝或证据不足及其依据；接受时生成锁定依赖的应用版本，灰度下发。发现退化时恢复已登记的基线。

执行面 · 单个 Agent 实例

Agent 内部五层

同一份应用版本登记角色、Skill 和工具绑定。模型选择、记忆访问和工具权限分别交给进程外的三个网关治理。图中的五层沿用 AgenticMesh 的设计。

层运行时职责版本与访问边界
模型经模型网关请求推理。网关按路由与预算选择提供方，支持切换与降级。本期冻结模型权重。经验蒸馏和模型更新后的上下文适配属于预留路径。
上下文组织系统指令、当前任务、示例与本步可见观测，供模型判断下一步。观测随任务推进而更新。对提示模板或示例集的持久修改形成版本候选。
记忆经记忆网关按作用域检索和写入经验、事实及其来源。后端可绑定向量库或图谱。运行时写入按既有权限执行。修改记忆组织方式、共享范围或访问策略需要版本验证。
Skill（技能）描述可复用的操作流程、适用条件与结果判据。时钟观测 Skill 指定读取基线、新测量和比较回执的步骤。反复有效的经验可以整理为 Skill 候选。通过控制面验证后绑定到新版本。
Harness（执行框架）装配工具、控制流程与子代理，执行选定的 Skill。环境调用经工具网关进行 MCP 绑定，并取得结构化回执。工具清单与流程随应用版本发布。每步执行记录与网关回执通过运行号关联。

本地已验证时钟 Skill 的 Python 执行器与 MCP 调用。模型网关、记忆网关、kagent 集群、A2A 交接以及跨层经验沉淀均为待验证设计。
