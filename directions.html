三个科学问题

高速固定翼集群仿真中，同一事件到达各成员的时间可能不同，多个成员的判断也可能来自同一条观测。这给分布式具身智能提出了三个可独立检验的问题。

异步局部状态表征

信息延迟或缺失时，哪些历史观测足以支持个体对当前状态的判断？

固定每次判断时已经可见的记录与上下文长度，比较“只保留最新值”和“保留来源、采样时刻与缺失状态”的摘要。按延迟分组统计判断误差与引用未来信息的次数。

A1 局部观测的时间与表征

群体协作增益

通信在什么条件下带来互补信息，又在什么条件下只会放大共同误判？

在同批事件和相同模型调用预算下，对照独立判断、转发同一来源和交换互补观测。后两组匹配消息量。以独立标注计算正确率的配对变化和共同误判率。

A2 共识与协作增益的度量

经验迁移与递归改进

从一次失败中形成的 Skill 改动，在什么条件下能改善未见任务？改进器自身的贡献如何识别？

先冻结模型和预算，在留出批次配对比较原版与候选 Skill，记录收益与退化。候选评价可复算后，再固定初始 Skill 和候选数，比较新旧改进器产出有效候选的比例。

第一阶段 · 基于离线数据搭建完整的 Agent 框架

第一阶段要交付一套可以接收任务、生成计划、调用 Skill、组织多个 Agent 协作并返回结果的执行框架。离线数据为环境工具提供输入。先并行搭建环境接口和单个 Agent，再接入 Skill、编排与通信。运行记录从首个实例开始采集。

建设任务首轮交付验收条件支撑方向
1　离线环境与工具接口把一份离线数据及其参考结果登记为带版本的样例。环境适配器通过 MCP 提供检索、读取工具，统一返回结果、来源和错误信息。对同一次查询返回一致的记录与来源。更换同一契约下的数据集，沿用同一套 Agent 和 Skill。P0
2　单个 Agent 的运行时以 kagent 承载 Agent 实例，接入模型、任务上下文、记忆、Skill 和执行框架（Harness）。给每次任务分配独立上下文和运行号。给定任务，实例能加载指令、调用模型、执行获准的工具并返回结果。启动新任务后，可核对上下文和记忆的读取范围。P0、A1
3　Skill 封装与注册接通任务 1、2。为数据检索、摘要和结果核验封装 Skill。每项登记适用条件、参数、执行入口、版本及返回格式。从注册表选取 Skill 后可独立运行。用一条正常输入和一条缺失输入验证返回值与错误处理。P0、B1
4　任务规划与应用编排在 AeroWeaver 中组合已注册的能力。把任务说明转成可执行的计划，列出步骤依赖、实例角色、可用 Skill 及完成条件。执行前能查看计划。更改任务要求后，相关步骤和 Skill 选择随之调整。一次工具失败后有明确的处理路径。A1、A2
5　多 Agent 通信与协作用 A2A 协议连接实例，按任务计划分派工作、传递中间结果并汇总。消息关联任务、步骤和证据来源。一个实例的结果能成为下游实例的输入。通过消息标识区分重复交接，超时后任务状态可追踪。P0、A2
6　运行证据与版本管理按 AgenticMesh 三面架构登记应用版本。由执行面归档计划、模型与工具调用、消息及结果，向控制面提供验收记录，向进化面提交失败样例。固定数据、任务和版本后能重放已记录的执行过程，独立复核最终结果。一次失败可定位到具体步骤及对应版本。P0、B2

首轮联合验收 · 从任务输入到协作结果

跑通一项任务。 输入“汇总指定时段的记录，并核查缺失项”。系统先给出计划，再由不同实例完成检索、汇总与核验，返回带记录引用的结果。用预先保存的参考答案核对缺失项与统计值。

换数据与任务。 在同一工具契约下替换离线样例，再把任务从“汇总记录”改为“比较两个时段”。检查哪些步骤复用，哪些步骤由编排器重新生成。

复现一次失败。 让一项工具调用返回缺失输入，核对 Skill 错误、A2A 交接状态和最终说明。按运行号重放记录，能找到首次失败的步骤与版本。

进入下一阶段的条件　执行框架通过联合验收后，先定义各实例的可见范围与消息投递规则，再开展 A1、A2 对照实验。积累可追溯反例后启动 B1，形成配对评价协议后启动 B2。两者均可复跑后再开展 C1。查看各方向实验与停止条件
